# Repair accounting — спецификация бота и мини-приложения

## 1. Общая идея

Это Telegram-бот для учета ремонтов с встроенным мини-приложением Telegram WebApp.

Система состоит из двух частей:

1. Telegram-бот
2. Личный кабинет / мини-приложение

Бот нужен для быстрого внесения и поиска ремонтов прямо в чате.
Личный кабинет нужен для просмотра базы, учета, настроек и работы с карточками в более удобном интерфейсе.

---

## 2. Основные сущности

### 2.1. Карточка ремонта

Карточка ремонта может содержать:

- фото
- пломбу
- сумму ремонта
- описание ремонта
- сумму детали
- историю изменений / этапов

### 2.2. Ремонт без пломбы

Если ремонт создается без пломбы, система создает внутренний виртуальный идентификатор.
В интерфейсе это показывается как `без пломбы`.

### 2.3. История карточки

Одна карточка может содержать несколько этапов:

- основная запись
- повторные ремонты
- изменения пломбы
- изменения суммы
- изменения ремонта
- изменения суммы детали

## 3. Telegram-бот: сценарии

### 3.1. Постоянные кнопки в чате

В чате у бота есть постоянная клавиатура:

- `🆕 Новый ремонт`
- `🔎 Найти`

Также есть главное постоянное сообщение:

- `Я бот записи и учета ремонтов`

Оно должно оставаться в чате и не удаляться.

### 3.2. Команды

Поддерживаются команды:

- `/start`
- `/new`
- `/find`
- `/cabinet`
- `/add`
- `/quick`
- `/today`

Также поддерживаются текстовые триггеры:

- `старт`
- `start`
- `🆕 Новый ремонт`
- `🔎 Найти`
- `поиск`
- `найти`

### 3.3. Новый ремонт с фото

Пользователь нажимает `Новый ремонт`.

Далее:

1. отправляет фото
2. может сразу в подписи указать данные
3. либо бот отдельно просит ввести данные

Формат поддерживается:

В строку:

`пломба, сумма, что сделал, деталь`

Или в столбик:

```text
пломба
сумма
что сделал
деталь
```

Поле `деталь` необязательно.

### 3.4. Новый ремонт без фото

При сценарии `Новый ремонт` доступен вариант:

- `💰 Без фото`

В этом режиме можно создать запись:

- без фото
- без пломбы
- только с суммой и описанием
- с необязательной суммой детали

Формат:

В строку:

`сумма, что сделал, деталь`

Или в столбик:

```text
сумма
что сделал
деталь
```

### 3.5. Повторный ремонт

Повторный ремонт запускается через:

`/add <пломба>`

Пример:

`/add 1542`

После этого:

1. ищется существующая карточка
2. пользователь отправляет новое фото
3. вводит новую пломбу, сумму, ремонт, деталь
4. запись сохраняется как новый этап той же карточки

### 3.6. Поиск по пломбе

Поиск работает:

- по основной пломбе
- по старым пломбам
- по пломбам из истории

Если карточка найдена:

- бот показывает карточку
- если фото валидное, показывает фото + подпись
- если фото битое или отсутствует, показывает текстовую карточку

### 3.7. Редактирование карточки в чате

У найденной карточки есть inline-действия:

- изменить
- удалить карточку

Редактирование в чате принимает:

В строку:

`новая пломба, сумма, тип ремонта, деталь`

Или в столбик:

```text
новая пломба
сумма
тип ремонта
деталь
```

При редактировании:

- старая пломба сохраняется в истории
- старая сумма сохраняется в истории
- старый тип ремонта сохраняется в истории
- старая сумма детали сохраняется в истории

### 3.8. Защита от дублей пломб

Если при создании или изменении вводится пломба, которая уже есть в базе пользователя:

- бот не должен молча перезаписывать
- такая пломба считается дубликатом

### 3.9. Очистка чата

Чат умеет:

- автоочищаться через заданное время бездействия
- вручную очищаться из настроек ЛК

При очистке:

- главное сообщение бота остается
- остальные сообщения удаляются

Если пользователь ломает сценарий ввода или вводит невалидные данные:

- бот удаляет служебные сообщения текущего сценария
- пишет `Начни сначала`
- потом удаляет и это сообщение

## 4. База данных

Используется SQLite.

Основные таблицы:

- `repairs`
- `repair_history`
- `repair_seal_aliases`
- `chat_main_messages`
- `user_settings`

### 4.1. repairs

Основная карточка:

- дата
- user_id
- photo_file_id
- seal_number
- work_done
- amount
- part_cost

### 4.2. repair_history

Этапы карточки:

- parent_repair_id
- дата
- user_id
- photo_file_id
- seal_number
- work_done
- amount
- part_cost

### 4.3. repair_seal_aliases

Хранит все старые и связанные пломбы карточки для поиска.

### 4.4. chat_main_messages

Хранит id главного сообщения в чате, которое нельзя удалять при очистке.

### 4.5. user_settings

Индивидуальные настройки пользователя:

- процент расходов
- какие поля показывать в карточке
- включена ли автоочистка
- время автоочистки

## 5. Личный кабинет / WebApp

Личный кабинет открывается как Telegram mini app.

Есть 3 основные вкладки:

1. `Учет`
2. `Ремонт`
3. `Настройки`

Нижняя панель вкладок закреплена.

### 5.1. Вкладка Учет

Показывает:

- валовую выручку
- расход на детали
- чистую без деталей
- `-30% / -35% / -40% / -45% / -50%`
- итог после вычета процента
- количество операций с суммой

Также есть фильтры периода:

- `1 неделя`
- `1 месяц`
- `3 месяца`
- произвольный диапазон через календарь

При нажатии на блок `Операций с суммой` показывается только список операций, где есть сумма.

### 5.2. Логика расчета в учете

Логика должна быть именно такой:

1. берется сумма ремонта
2. из нее вычитается сумма детали
3. с остатка считается процент расходов

Пример:

- сумма ремонта: `1000`
- деталь: `100`
- чистая без деталей: `900`
- если выбран `40%`, то:
  - `-40% = 360`
  - итог после процента = `540`

### 5.3. Вкладка Ремонт

Это сетка карточек ремонта.

Сверху:

- поиск по карточкам

Ниже:

- плитки карточек
- фото в миниатюре
- если фото нет, показывается `?`

Каждая карточка открывается как раскрывающийся блок.

Внутри отображаются:

- пломба
- сумма
- ремонт
- сумма детали
- история этапов

В зависимости от настроек эти поля могут скрываться.

### 5.4. Действия внутри карточки

В карточке есть кнопки:

- редактировать
- удалить

#### Редактирование

Открывает модальное окно с 4 полями:

- Пломба
- Сумма
- Ремонт
- Сумма детали

#### Удаление

Удаляет карточку прямо из ЛК после подтверждения.

### 5.5. Вкладка Настройки

Сейчас содержит:

#### Процент расходов

Выбор одного значения:

- `30`
- `35`
- `40`
- `45`
- `50`

#### Автоочистка чата

- включить / выключить
- выбрать время:
  - `1 мин`
  - `3 мин`
  - `5 мин`
  - `10 мин`
- кнопка `Очистить чат`

#### Что показывать в карточке

Переключатели:

- Пломба
- Сумма
- Ремонт
- Сумма детали
- История изменений

#### Экспорт базы

Кнопки выгрузки:

- `JSON`
- `CSV`

Экспортирует только записи текущего пользователя.

## 7. API мини-приложения

Текущие endpoints:

- `GET /cabinet`
- `POST /api/cabinet/repairs`
- `POST /api/cabinet/photo`
- `POST /api/cabinet/card/update`
- `POST /api/cabinet/card/delete`
- `POST /api/cabinet/settings`
- `POST /api/cabinet/export`
- `POST /api/cabinet/clear-chat`

### 7.1. /api/cabinet/repairs

Возвращает:

- карточки
- сводку
- операции
- пользовательские настройки

### 7.2. /api/cabinet/photo

Отдает изображение карточки:

- из локального файла
- или из Telegram file_id

### 7.3. /api/cabinet/card/update

Редактирует последнюю актуальную запись карточки.

### 7.4. /api/cabinet/card/delete

Удаляет карточку из базы.

### 7.5. /api/cabinet/settings

Сохраняет пользовательские настройки.

### 7.6. /api/cabinet/export

Выгружает базу пользователя:

- `json`
- `csv`

### 7.7. /api/cabinet/clear-chat

Очищает чат пользователя, оставляя главное сообщение.

## 8. Особенности логики по пользователям

Бот рассчитан на то, что:

- у каждого пользователя свои записи
- у каждого пользователя свои настройки
- поиск, учет, ЛК и экспорт работают в рамках `user_id`

То есть базы разных пользователей не должны смешиваться логически, даже если физически они лежат в одной SQLite.

## 9. Текущие ограничения и нюансы

### 9.1. Личный кабинет зависит от внешнего URL

Мини-приложение открывается через `WEBAPP_URL`.
Если внешний tunnel-адрес меняется, кнопку ЛК нужно обновлять.

### 9.2. Фото в старых карточках

Если у старой карточки битая ссылка на фото:

- бот не должен падать
- вместо этого должен показать текстовую карточку

### 9.3. Главное сообщение

Главное сообщение должно:

- существовать в чате постоянно
- не удаляться очисткой
- содержать reply keyboard с быстрыми кнопками
